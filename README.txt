SafeSpend PWA V7.5 · 单次额外收入储蓄联动校正版

本版对“单次额外收入 → 储蓄”的整条链路进行了重新检查和显式拆分。

检查结论：
原有记账引擎实际上已经会把单次额外收入中的“本次优先储蓄”计入真实储蓄余额，
也会进入日期范围内的储蓄净增和结果页预计储蓄增长。
问题主要在于储蓄页把它和周期收入储蓄合并显示为一个“收入”类别，
视觉上看不出来单次额外收入是否真正联动。

本版改为：

储蓄变化明细明确拆分：
- 周期收入储蓄
- 单次额外收入储蓄
- 周期结束结余转储蓄
- 零花钱转储蓄
- 专项结余转储蓄
- 手动额外储蓄
- 外部直接存入银行
- 储蓄取用 / 超支扣减
- 日常储蓄转银行

“单次额外收入储蓄”与“手动额外储蓄”现在是两个不同概念：
1. 单次额外收入储蓄：
   记录一笔单次额外收入时，在“本次优先储蓄”中分配的金额。
2. 手动额外储蓄：
   单独点击“记额外储蓄”录入的金额。

联动检查：
- 单次额外收入的优先储蓄 → 日常储蓄余额
- → 当前储蓄资产
- → 储蓄变化的本月 / 本年 / 当前周期 / 自定义范围
- → 结果页预计储蓄增长
- → 银行转存提醒的当前日常储蓄
以上均继续使用同一底层金额，不重复计数。

同时，未来新记录的收入会保存 planNameAtRecord，
即使之后删除收入计划，历史流水和储蓄变化仍能保留原收入来源名称。
